## Themes and layout

In **Settings → Appearance**, **Layout** can be **Full page**, which shows the community as a full-screen app, or **Inside your theme**, which places it between your theme header and footer. You can override the layout files: see [Template overrides](/spacebay/developers/template-overrides/).

## Multisite

- SpaceBay was tested on single sites and on multisite (network activation and sub-sites).
- Signing up only works when the network administrator allows new accounts (**Network Admin → Settings → Allow new registrations**).
- The two-factor policy is set per site. Someone who logs in on another site of the network where no code is required is logged in on every site, so use the same policy on each site.
- Deleting the plugin with **Delete all data when the plugin is deleted** on removes the data and images from every site in a network.

## Plugins that use the same addresses

<span class="sb-badge sb-badge--since">Since 1.3.0</span> This matters only when you choose **At the home address** under **Community home location**. See [Community home location](/spacebay/user-guide/community-home-location/). The community then answers addresses such as `/events/`, `/members/`, `/posts/` and `/search/`. Any plugin or theme that uses one of them (a page, a post type archive or a rewrite rule) is a clash. For example, an events calendar with its archive at `/events/`, a members page of a social plugin at `/members/`, or a WooCommerce shop at `/shop`. Plugins are found by what they register, not by name, so this list is not complete. SpaceBay does not name or test them one by one.

- SpaceBay refuses to choose **At the home address** while a clash exists, and lists the addresses.
- A clash that appears later is shown in Site Health, in an admin notice and in the settings. SpaceBay never changes your choice by itself.
- A WooCommerce shop at `/shop` clashes only when SpaceBay Pro member shops and the **Shop page** option are on, because only then is `/shop/` a community address.
- The community wins for its own names. Rename the page or the plugin's address, or choose **At a page address**.
- Language-prefix plugins (Polylang or WPML in directory mode, which put `/fr/` in front of every address) are not supported with **At the home address**.
- A subsite of a subdirectory multisite at the same path is not detected.
- Cache plugins, host caches and CDNs must not cache the home address or the community pages.

## Right-to-left languages and translation

The portal supports right-to-left languages and was tested in Arabic. SpaceBay is translation ready: see [Translation](/spacebay/developers/translation-and-building/).

## Page-cache plugins

SpaceBay marks portal pages as not cacheable (`DONOTCACHEPAGE` and no-cache headers), so members always see their own data.

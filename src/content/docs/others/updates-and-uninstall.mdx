## Updates

### SpaceBay (free)

Updates come from WordPress.org. New versions appear on **Dashboard → Updates** and on the Plugins screen like any other plugin, and WordPress can install them automatically.

### SpaceBay Pro <span class="sb-badge sb-badge--pro">Pro</span>

Pro does not update itself yet. To update it:

1. Download the new **spacebay-pro.zip** from your wpanchorbay.com account.
2. Go to **Plugins → Add New Plugin → Upload Plugin**, choose the zip and click **Install Now**.
3. Confirm **Replace current with uploaded**.

### Bought on CodeCanyon

CodeCanyon buyers can keep using the free Envato Market plugin for updates:

1. Download and install the Envato Market plugin from [envato.com/lp/market-plugin](https://www.envato.com/lp/market-plugin/).
2. Create a personal token at [build.envato.com/create-token](https://build.envato.com/create-token/) with the default permissions.
3. Paste the token in **Envato Market** in your WordPress admin and save.
4. New versions now appear on **Dashboard → Updates**.

You can also download the latest zips from your CodeCanyon Downloads page and upload each one with **Replace current with uploaded**.

Your community data is kept during updates. SpaceBay Pro 1.0.0 needs SpaceBay 1.0.0 or newer.

Updating from 1.0.0 to 1.1.0 changes no database tables. If your site is behind a proxy or CDN, open **Tools → Site Health** after updating: SpaceBay tells you whether it can tell visitors apart, and the `spacebay_client_ip` filter fixes it (see [Hooks and filters](/spacebay/developers/hooks-and-filters/)).

Updating from 1.1.0 to 1.1.1 adds one small table (the member decision log), a `comment_id` column to the notifications table and an `entered_at` column to the profiles table. Everyone who was already in your community is marked as a member, so member approval does not hold existing members.

SpaceBay 1.1.2 was never released on its own, so an update from 1.1.1 goes straight to 1.2.0 and brings the 1.1.2 changes with it. One change needs a look after updating. The login, sign-up and Pro code forms now accept requests only from your own site address. If members also reach the site through a `www.` or subdomain address, add that address with the WordPress `allowed_http_origins` filter, or their login is refused. See [Security and limits](/spacebay/user-guide/security-and-limits/).

Updating from 1.1.1 to 1.2.0 adds the **Import and export** screen. The update adds database tables for import and export jobs and for redirects from old addresses. SpaceBay Pro 1.1.0, which adds shops, profile fields and Pro settings to exports, needs SpaceBay 1.2.0 or newer.

## Deactivate and uninstall

Deactivating keeps all data. Deleting the plugin keeps all data unless **Delete all data when the plugin is deleted** is on in Settings. When it is on, deleting removes SpaceBay tables, settings, capabilities (including the moderator capability given to single members), cached data and the uploaded images in `wp-content/uploads/spacebay/` from every site in a network.

**SpaceBay Pro** <span class="sb-badge sb-badge--pro">Pro</span> keeps its data the same way. When **Delete all data when the plugin is deleted** is on, deleting Pro also removes the calls tables, the custom profile fields and members' two-factor settings. With that setting off, deleting Pro keeps its data, so installing Pro again brings the features back as they were.

When a WordPress user is deleted, their SpaceBay profile, photo, cover, notifications, posts, comments, likes, images, memberships, points, badges, event answers and the events they organized are deleted too. Images uploaded but never posted are removed after a day.
